### Switches

- `GOLF_NP=offline`: signed-out console instead of the local account. `GOLF_ONLINE_ID=<name>`: the local online id (default `Golfer`).
- `GOLF_ENTITLEMENTS=original`: report no add-ons.
- `RESOGUN_IME_TEXT=<text>`: answer every keyboard dialog with this text (needed for unattended boots: the on-screen dialog waits for a real controller or keyboard).
- `RESOGUN_FILE_TRACE_MATCH=<text>`: log every open whose path contains the text, found or not.
- `RESOGUN_FAULT_PEEK=<reg><+|->0x<offset>`: print the string at that address in a fault report.
- `RESOGUN_VERIFY_PREPARED=1`: compare what the draw-preparation workers read with a fresh read and log differences.
- `RESOGUN_NGS2_TRACE=1`: print the Ngs2 voice parameters the game sends. `RESOGUN_NGS2_MIX=0`: silent output. `RESOGUN_AUDIO_DUMP=<prefix>`: raw samples of every audio port.
- `GOLF_NP_TRACE=1`: log each distinct guest call site of the shared NP answers. `GOLF_PEEK="offset:bytes,*offset+delta:bytes"` (hex, `*` follows the pointer stored there) prints guest memory ranges when they change, every `GOLF_PEEK_MS` ms (default 2000). `GOLF_BREAK="d91790,a62080"` (hex guest offsets, up to 8, Windows) puts an int3 on each site and prints the thread, rdi, rsi, rdx, the u32 at rsi+0x18 and the caller for the first 40 hits, then re-arms after one step (runtime `8136a31`).
- `RESOGUN_TOGGLE_FILE=<file>`: a number in the file switches renderer optimizations off while the game runs (bits in `gpu/shim/resogun_toggles.h`).

## Performance and display (2026-11-18)

- Profiler: `GOLF_PROFILE=<seconds>` (runtime `120994f`) samples guest and runtime threads every 4 ms and prints per-thread CPU and the top 40 guest callers. `GOLF_PROFILE_THREAD=<name>` limits it to one thread (sampling every thread slowed the game to 4-13 FPS); `GOLF_PROFILE_WAITS=1` also samples threads that are waiting.
- Frame loop: the frame object is at image+0x2cea1c0, with the target FPS at +0x24ec (30 by default, set at 0xb9ab5) and the flip-rate flag at +0x24f0. The pacing loop at 0xfb3110 calls `sceVideoOutWaitVblank` until 60/target-1 vblanks pass. The main thread then submits the flip and blocks in `sceKernelWaitEqueue` at 0xfbd04a until the flip completes. Most of a slow frame is spent in these two waits, not in CPU work.
- 60 FPS, first try: the game switches between 30 (0xeadb0, with `SetFlipRate(1)`) and 60 (0xeacf0) itself and checks `==60` in about 20 places. Holding the target at 60 crashed at 0xeb7a1 and, with a guard, at 0x2f6fba, because the 60 path expects objects such as the one at 0x2c99d30. The change was reverted. Game logic above 60 FPS does not exist in this game.
- 60 FPS, working (runtime `4f550fc`): the game has a PS4 Pro display option (save field +0x2c; 2 is frame rate priority) that sets the flag at 0x2cea1d9. With it, 30 Hz scenes keep flip rate 0 unless one of five scene objects of the frame object is active (+0x13150, +0x181b0, +0x181a8, +0x12bda, +0x12c18), which drops the tee, shots and flyover to 30. The runtime ports golf-fix v41's patch (51 conditional jumps become nops, all behind the flag) and replaces its vsync-interval change at 0xeac3a with a stub that gives 1 only with the flag on. `frame_rate_priority=1` (settings.ini, default) makes the option read as 2 at 0xbced47 and 0x14a2d7. In that mode the game renders 3200x1800. Measured: free roam 59.4-59.8 FPS (was 30.0) with 296-299 of about 300 flips one vblank apart; hole 1 tee 58.4 FPS (286 of 292); the drive, ball flight and result played. Hitches of 0.4-0.7 s in the first shot came from pipeline compiles on a fresh shader cache.
- golf-fix v22 (runtime `4f550fc`): fragment-shader implicit-LOD samples of single-level images whose min and mag filters match now sample at LOD 0, because derivatives are undefined inside divergent control flow (golf-fix: horizontal lines in shadows). After it, the hole 1 hole map drew green with the pin; the run before it showed the map black. Whether it changes the face faults is not checked.
- FSR 1: with `sharpening=1` the presenter upscales the 3200x1800 PS4 Pro frame to a larger window with EASU, then RCAS sharpens it (runtime `6d095aa`). At 3779x2126 the output's mean color matched the source frame.
- Not possible from the presenter: DLSS and FSR 2/3 (upscaling or frame generation) need per-pixel motion vectors and depth from the game's own renderer. Driver-level frame generation (NVIDIA Smooth Motion, AMD Fluid Motion Frames) works on any Vulkan window and is the available route. Native 4K would need the game's 3200x1800 render targets resized.
- 30 FPS (runtime `5fbddb3`): the measured 24 FPS was caused by the measuring tool. `RESOGUN_FRAME_STATS` printed each stall report from the present thread and blocked on the output pipe for 40-60 ms before the flip event fired; main waited for that event, so the next frame stalled too, about 11 times in every 5 s. Printed from a logger thread, free roam holds 30.0 FPS, with 150 of 150 flips two vblanks apart and a p99 frame of 34 ms. No other change was needed. Measured with another project's game loading the PC.
- Texture packs (2026-11-19, runtime `2e03400`): `texture_dump=` writes each eligible texture once as DDS, keyed by an XXH3 of its guest bytes; `texture_pack=` samples `<key>*.png` instead, decoded on a worker thread with a full mip chain. `tools/texture_pack.py` converts and upscales. A tinted pack of all 1,273 dumped textures recolored the scene in game. A 2x Lanczos pack held free roam at 58.8-59.4 FPS (GPU idle about 69%, as without a pack) with over 1,024 textures replaced in 9.9 GB of video memory. Details and limits: `docs/texture-packs.md`. An AI upscale (Real-ESRGAN) is not done yet.
- Face shading patches (2026-11-19, open): faces and necks show hard-edged, polygon-shaped patches and a curved seam down the left cheek, with the left half slightly darker. Character-select thumbnails, which have no shadow pass, show the same seams, and golf-fix v22 did not change them. Face draw: VS `2f825e5d`, PS `e018fbaa`; the PS interpolates all 11 inputs by hand from per-vertex data with `gl_BaryCoordEXT`. Ruled out: shadows, the 17-layer 256x256 RGBA8 vertex texture (layer count right), V_MOVRELS translation, the vertex-index offset, barycentric order, the 32-lane writelane limit (highest lane 26), 10:10:10:2 formats (none in the draw), depth layering (one face draw per pass, plain depth test) and flat inputs (none). The VS builds a normal from finite differences of a height map in that vertex texture. A debug build that returned a flat height (w = 0.5) for that VS still showed the cheek seam, so that path is ruled out too. The seam follows a UV island edge on the left side, not the face's center line. A run with every sample in the face pixel shader forced to LOD 0 looked smoother by eye, but a high-pass view of the same crop still shows faint facet lines, so that test is not conclusive. Guest-memory mips of all four BC3 face arrays agree with mip 0 (average color per layer), and the upload path for micro-tiled mip arrays checks out. Runtime `c27a880` fixes a related sampler fault found on the way: GCN `MIP_FILTER` None (base level only) was mip-mapped on PC; it now clamps the LOD to [0, 0.25]. Menus, free roam and the editor drew normally after it; whether it changes the faces is not shown. The face cause is still open. Runtime `a104224` adds texture layers, mips and tile mode and every vertex attribute's format to the frame capture.
- New diagnostics: a "Flip latency" stats line (guest submit to GPU-thread queue, about 0.2 ms; queue to flip, about 16 ms; intervals in vblanks); `RESOGUN_SLOW_WAITS_THREAD=<name>`; slow sleeps and flip waits print the guest call site (image base 0x800000000); `RESOGUN_EQUEUE_WAITERS=1` lists each event queue's waiting threads. Main (0xfbd04f) and `BackgroundDraw` (0xfb768a, loading screens only) share the Flip queue.
